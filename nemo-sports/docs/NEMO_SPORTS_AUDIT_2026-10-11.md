# NEMO Sports end-to-end audit — 2026-10-11

## Executive summary

This is a read-only audit of the deployed site plus a set of small, local code fixes on the Arena working branch. Production behavior, source-code behavior and local test results are separated below. **Nothing was changed in production**: no database rows, deployment settings, credentials, matches, news, teams, players, competitions or broadcast records were edited or deleted. No deployment or paid service was initiated.

The most important confirmed defects are:

1. The deployed competition filter for English Premier League includes similarly named Hong Kong, Bermuda and Saint Kitts competitions.
2. The deployed page's `status=postponed` filter returns all 184 matches, while the versioned API rejects the same status.
3. Public news is stale; all 14 configured sources have never been fresh, ingestion has no configured token, and the feed includes clearly non-sports company stories under football categories.
4. A current provider response labels SportScore data as “Powered by Football-Data.org”; the match API also combines provider and editorial rows under provider-level metadata.
5. Several team links generated by `/teams` resolve to 404 even though those teams appear in the live standings response.

Local fixes were implemented for exact competition filtering, consistent supported status filtering, screen-reader state on match-filter toggle buttons, and provider-correct attribution on Football-Data wrapper responses. All are **local only** pending review and deployment. Production still shows the original competition, status and attribution behavior.

## Prioritized findings

### AUD-01 — P1 · Competition selection returns similarly named leagues

**Status:** Production issue confirmed; minimal local code fix and regression test applied; production remains unchanged.

- **Reproduction:** Open `https://nemo-sports.vercel.app/matches?competition=english-premier-league&date=2026-10-11`.
- **Observed:** Four returned cards were from Hong Kong Premier League (two matches), Bermuda Premier League and Saint Kitts Nevis Premier League. No English Premier League match was in that result set. The page therefore returned unrelated competitions for an exact competition selection.
- **Root cause:** `fixtureBelongsToCompetition` treated substrings as competition aliases. A shared phrase such as “Premier League” could match a different competition. The page also derived selector options from the current fixture feed, so a requested competition absent from that feed could lose its visible selected option.
- **Minimal local fix:** Compare normalized provider IDs and known aliases exactly; retain a selected canonical competition option even when the current feed has no fixture for it. Preserve exact matching for unknown/provider competition names.
- **Files changed:** `lib/competition-catalog.ts`, `app/matches/page.tsx`, `components/match/MatchesFilters.tsx`, `scripts/verify-repairs.test.ts`.
- **Regression risk:** A provider spelling not present in the canonical alias set can now yield no results instead of an accidental partial match. Exact provider IDs and provider-name selection are covered by regression tests; adding an alias should be explicit.
- **Acceptance:** Selecting the English Premier League returns only fixtures whose exact provider ID/name is an English Premier League alias; zero matches is shown as zero, not filled with other “Premier League” competitions. The selected competition remains visible when its date has no fixtures. Page and API filters agree.
- **Test:** New unit test covers English Premier League vs Bermuda, Hong Kong, and MEX Liga Premier near-matches, plus exact matching for an unknown provider name. It passed in the local repair suite.

### AUD-02 — P1 · Match-state filters disagree and can silently show everything

**Status:** Production issue confirmed; minimal local code fix and regression test applied; production remains unchanged.

- **Reproduction A:** `https://nemo-sports.vercel.app/matches?status=postponed`.
- **Observed A:** The deployed page showed 184 matches; the displayed counts were 184 total, 27 live, 30 upcoming and 127 finished. The requested postponed filter did not filter the list.
- **Reproduction B:** `https://nemo-sports.vercel.app/api/v1/matches?date=today&status=postponed`.
- **Observed B:** API returned HTTP 400 with `Unsupported status`.
- **Root cause:** The page-side provider filter defaulted unknown statuses to “include”; API validation accepted only a narrower vocabulary. The status chips also did not offer the exact interrupted states reported by providers.
- **Minimal local fix:** Share the supported status vocabulary and validation between page/API; reject unknown page states with an explicit unavailable/error message rather than all matches; filter and count `postponed`, `cancelled`, `suspended` and `abandoned` using normalized provider states; render those state chips when results exist or when selected. Demo filters were given equivalent supported-state behavior.
- **Files changed:** `lib/match-query.ts`, `lib/provider-match-filter.ts`, `lib/filters.ts`, `app/matches/page.tsx`, `components/match/MatchesFilters.tsx`, `scripts/verify-repairs.test.ts`.
- **Regression risk:** Providers can use different raw status strings. This change deliberately uses the shared normalized `matchStateOf` mapping; newly encountered provider vocabulary still needs an adapter mapping and test rather than a permissive fallback.
- **Acceptance:** For each supported state, the page and API return only matching provider-reported states, with matching counts. Invalid states never display all matches. A valid filter with an unavailable provider reports unavailable data rather than inventing an empty successful feed.
- **Test:** New unit coverage independently filters/counts `postponed`, `cancelled`, `suspended`, `abandoned`, accepts them in page/API validation, and rejects `still-live`. Local API probes after the final build returned HTTP 200 for `postponed` and `cancelled` (zero matching local fixtures), HTTP 400 for `bogus`; the local page rendered its unsupported-state response. A dated `status=postponed` local API probe returned 503 when the provider was unavailable, so a provider-backed success for that dated request remains unverified locally.

### AUD-03 — P1 · News ingestion is disabled/stale and published items include non-sports stories

**Status:** Production data/configuration issue confirmed; no production configuration or record was changed. Existing classification/moderation paths were dry-run only.

- **Reproduction:** `https://nemo-sports.vercel.app/api/v1/news?limit=100` and `https://nemo-sports.vercel.app/api/cron/fetch-news`.
- **Observed:** Public feed metadata reported 13 items, `stale=true`, `lastSuccessfulUpdate=null`, last failed attempt `2026-10-09T01:02:27.866Z`, 14 enabled sources and 0 fresh / 14 never fresh. The cron endpoint returned `not_configured` and states that `NEMO_INGEST_TOKEN / CRON_SECRET` is missing.
- **Observed data-quality examples:** The public feed files an El Sewedy/CIRA Damietta university-investment headline under `Egyptian Football`; a previous read-only production result also included an Al Ahly Sabbour property/residence story associated with Al Ahly. A Veszprém–Al Ahly IHF handball story was stored under `Egyptian Football`.
- **Root cause:** Scheduled ingestion is not configured and stored legacy rows have not been re-moderated/re-categorized using the current rules. The current pure classifier rejects the two commercial/non-sports examples for quarantine and classifies the IHF headline as `Handball`, but the deployed records remain unchanged until a protected workflow runs.
- **Minimal safe path:** Deployment owner must configure one accepted ingestion secret (`CRON_SECRET`, `VERCEL_CRON_SECRET`, or `NEMO_INGEST_TOKEN`, sent as a Bearer token or the route's supported token query) and durable `DATABASE_URL`. Then run the existing moderation and recategorization tools in dry-run mode, review the report, and use an authorized, owner-approved apply step. The moderation process hides/quarantines rather than deletes; the recategorizer changes category fields only. Do not simply relabel commercial headlines as sports.
- **Files/code inspected:** `app/api/cron/fetch-news/route.ts`, `lib/news/relevance.ts`, `lib/news/categorize.ts`, `lib/news/moderation.ts`, `scripts/moderate-news.ts`, `scripts/recategorize-news.ts`. No production record was edited.
- **Regression risk:** Al Ahly and Zamalek have teams in multiple sports; broad club-name matches are not sufficient to quarantine or categorize an article. The existing classifier's dry-run and review bucket must be preserved.
- **Acceptance:** Authenticated scheduled ingestion reports durable Postgres storage, successful current timestamps and fresh sources; no non-sports commercial article is published in football categories; IHF handball content is categorized as Handball; every quarantined item retains its record and provenance. Unauthorized cron requests still fail closed.
- **Test:** A local pure-function dry run on the Al Ahly Sabbour residence and El Sewedy/CIRA venture titles returned `reject` / `non-sport-entity`, with auto-quarantine eligibility true. It made no store/API write. A separate local pure classification of the exact IHF headline returned `Handball`. These results do not mean deployed records have changed.

### AUD-04 — P2 · Match API provider metadata does not describe all returned rows

**Status:** Production response-shape/provenance issue observed; not changed because the public API contract needs an explicit mixed-source design.

- **Reproduction:** `https://nemo-sports.vercel.app/api/v1/matches?date=2026-10-09`.
- **Observed:** Five rows carried `editorialUpdatedAt` and `sourceUrl:null`, with `status:"scheduled"` and null scores, while response-level metadata stated `provider:"sportscore"`, `source:"provider"`, `degraded:false`. The corresponding `/matches/al-fateh-vs-al-ahli` page explicitly identifies its source as NEMO editorial data. This does not establish that every returned row is editorial, but the response-level provider label is insufficient to distinguish merged editorial rows from provider rows.
- **Root cause:** `corrected()` merges admin/editorial fixtures into a provider result, but `GatewayResult` and `/api/v1/matches` expose one response-level source/provider and no per-row provenance.
- **Minimal fix proposal:** Preserve all rows and existing endpoint behavior, but add a documented row-level origin (provider/editorial) or explicitly report a mixed source in API metadata. Add contract tests for provider-only, editorial-only and mixed results. Do not drop admin records or mark them as provider data.
- **Relevant files:** `lib/sdl-gateway.ts`, `lib/admin-matches.ts`, `app/api/v1/matches/route.ts`.
- **Regression risk:** A source-contract change can break existing API clients and page filters that currently treat `source:"provider"` as a content gate. Design and version any contract change before implementation.
- **Acceptance:** Consumers can identify the origin of each fixture; aggregate metadata is truthful for mixed feeds; editorial fixtures remain visible and provider failures remain honest.
- **Test:** Production response above. No source change or data migration was made.

### AUD-05 — P2 · Past editorial fixtures remain scheduled without results

**Status:** Production data-quality concern confirmed; manual editorial review required; no records were changed.

- **Reproduction:** `https://nemo-sports.vercel.app/api/v1/matches?date=2026-10-09` on 2026-10-11, and `/matches/al-fateh-vs-al-ahli`.
- **Observed:** Five fixtures for Friday 9 October remained `scheduled` with null scores after their scheduled times had passed. The detail page says no event/statistics are currently recorded and attributes the record to the NEMO editorial register. The five slugs are `al-fateh-vs-al-ahli`, `al-nassr-vs-al-diriyah`, `borussia-dortmund-vs-werder-bremen`, `lens-vs-lyon`, and `malaga-vs-espanyol`.
- **Root cause:** Editorial records persist after kickoff until an editor/provider confirms their result or status; a scheduled time alone does not establish a final score or whether the fixture was postponed.
- **Minimal safe fix:** An authorized editor should verify each record against a permitted source, then update its status/time/score through the existing workflow. Until verified, expose it as unconfirmed and not upcoming. **Do not guess results, automatically finalize, or delete records.**
- **Relevant files:** `lib/admin-matches.ts`, `db/admin-matches.json`, `lib/match-state.ts`, match detail/API routes.
- **Regression risk:** Automatically converting every past scheduled match to finished would fabricate outcomes; a stale scheduled fixture may have been postponed or delayed.
- **Acceptance:** Past unconfirmed fixtures are not presented as confirmed upcoming matches; the UI/API clearly expose unknown status and source; scores change only after verified editorial/provider data.
- **Test:** Read-only production API and page checks. No admin access was available and no records were touched.

### AUD-06 — P2 · Provider attribution says Football-Data.org for SportScore data

**Status:** Production mismatch confirmed; source-level fix and regression test applied locally; deployment required.

- **Reproduction:** `https://nemo-sports.vercel.app/api/v1/football-data/standings?competition=PL` and `/api/v1/football-data/scorers?competition=PL`.
- **Observed:** Responses identify `provider:"sportscore"` but include attribution `Powered by Football-Data.org` and the Football-Data.org URL. The standings/scorers are fresh SportScore responses.
- **Root cause:** `lib/football-data.ts` assigned the Football-Data attribution unconditionally, even when the SDL had fallen back to another provider.
- **Minimal local fix:** Added `attributionForProvider`: preserve Football-Data attribution for `football_data`, return SportScore attribution for `sportscore`, and use a neutral source label for other providers rather than falsely attributing them to Football-Data.org. The status endpoint continues to identify the Football-Data integration itself.
- **Files changed:** `lib/football-data.ts`, `scripts/verify-repairs.test.ts`.
- **Regression risk:** Other configured fallback providers may need a provider-specific URL/label added as their terms require; the neutral fallback intentionally avoids inventing a legal link.
- **Acceptance:** `meta.provider` and `meta.attribution` identify the same actual upstream provider; status/configuration metadata continues to describe the Football-Data integration.
- **Test:** Added helper-level tests for Football-Data, SportScore and an unmapped provider. Local typecheck, full check and build pass. The local environment cannot obtain provider-backed standings, so a post-fix live API response has not been tested. Production remains unchanged.

### AUD-07 — P2 · Team directory links resolve to 404 despite provider rows

**Status:** Production issue confirmed; root cause not established; no speculative route patch.

- **Reproduction:** `/teams/Arsenal` (also previously checked: Liverpool, Manchester City, Real Madrid and lowercase `arsenal`) returns the “team not found” 404.
- **Counter-evidence:** `/api/v1/football-data/standings?competition=PL` returns a fresh 20-row table containing exact team IDs `Arsenal` and `Liverpool`. The team directory links to these team IDs.
- **Likely area:** `app/teams/[slug]/page.tsx` has a fallback that searches real league tables, but that fallback is not resolving these production routes. Possible causes include cached 404s, provider/rate-limit behavior during the multi-table lookup, or deployment/source mismatch; the public evidence does not distinguish them.
- **Minimal fix proposal:** Inspect authorized production logs/provider attempts and cache state first. Keep resolution exact by provider ID; do not fuzzy-match unrelated teams. Fix only the proven failure path.
- **Files to inspect:** `app/teams/page.tsx`, `app/teams/[slug]/page.tsx`, `lib/football-data.ts`, `lib/sdl-gateway.ts`.
- **Regression risk:** Loose name matching can route one team to another or create false indexable pages.
- **Acceptance:** Every team emitted by `/teams` links to a 200 detail page with the correct provider row; genuinely absent teams still return a stable 404; provider outages are not cached as permanent 404s.
- **Test:** Production page and API reads only. Not reproducible with the local provider-disabled preview.

### AUD-08 — P2 · Player profile and league top-scorer totals disagree

**Status:** Production values confirmed, cause unverified; no values were overwritten.

- **Reproduction:** `https://nemo-sports.vercel.app/players/erling-haaland` and `/api/v1/football-data/scorers?competition=PL`.
- **Observed:** The player detail page reported 4 matches, 3 goals and 337 minutes. The Premier League top-scorer API reported 5 appearances and 5 goals. - **Root cause:** Unverified. The player detail's provider response does not expose a season name (`seasonName` was null in source inspection); the leaderboard is competition-scoped. They cannot safely be treated as the same season/scope.
- **Minimal fix proposal:** Reconcile only when provider identity, competition and season are available. If the profile is unscoped, label it explicitly as provider-reported/unscoped and do not compare it as the current league total.

- **Regression risk:** Choosing one number without a season/source contract may overwrite a valid but differently scoped stat; the source may update asynchronously.
- **Acceptance:** Same player + same competition + same season produce consistent totals, or the UI clearly distinguishes differing/unavailable scopes; no statistics are inferred.
- **Test:** Read-only production page/API checks. No source patch.
